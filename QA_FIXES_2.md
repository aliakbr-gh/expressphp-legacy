# ExpressPHP QA fixes, round 2

Fixes for every finding in [CLAUDE_QA_REVIEW_2.md](CLAUDE_QA_REVIEW_2.md) (R2-01 to R2-14). Applied 2026-10-14 on top of
commit `e0af56d`.

Also in this change:

- **Removed:** `CLAUDE_QA_REVIEW.md`, `CODEX_QA_REVIEW.md`, `CURSOR_QA_REVIEW.md` and `QA_FIXES.md`. Their history is
  in Git.
- **Git rename:** the case-only rename `src/Http/IpAddress.php` → `src/Http/IPAddress.php` is staged with `git mv`.
  Commit `e0af56d` had renamed the class but not the tracked file, so autoloading would have failed on Linux.

The three items left open in round 1, FW-03, FW-05 and FW-07, are also fixed here; see
[Round-1 open items](#round-1-open-items).

## Behavior changes

| Change | Who is affected | Finding |
|---|---|---|
| A request with more than 50 validation errors returns the first 50 plus "Additional errors were omitted." | Clients that display every error | R2-01 |
| A JSON object or list with more than 1,000 entries is rejected anywhere in the body, not only under `*` rules | Clients sending very large objects | R2-01 |
| A password containing a NUL character returns 422 instead of 500 | None in practice | R2-03 |
| `X-Request-ID` is always generated by the server. The client's value is logged as `client_request_id`. | Apps that expected their own id echoed back | R2-13 |
| A JWT whose `iss`, `sub`, `jti` or `aud` has the wrong type, or whose `sv` isn't an integer, returns 401 | Only tokens not issued by this API | R2-11 |
| Templates fail with 500 on PHP warnings, and views send a default `Content-Security-Policy` that blocks inline script and style | Views with inline `<script>` or `style` | R2-06, R2-14 |
| SMTP requires TLS 1.2 or 1.3 | Relays that only offer TLS 1.0 or 1.1 | R2-07 |
| `cli/make` rejects reserved words, such as `list`, as class names | Generator users | R2-14 |
| `Password::configure()` defaults to cost 12 when `bcrypt_cost` is missing, matching the class default (it was 10) | Configs without `password.bcrypt_cost` | — |

## Fixes by finding

### R2-01 — Quadratic unknown-key check and error amplification

- `src/Validation/Validator.php`:
  - `unknownKeyErrors()` appends errors by reference instead of copying arrays, so it runs in linear time;
  - it stops once 51 errors are collected;
  - it counts visited keys against `MAX_EXPANDED_FIELDS`, which is 10,000;
  - it rejects any object or list with more than 1,000 entries before walking into it;
  - the new `limitErrors()` returns at most 50 messages plus "Additional errors were omitted."
- **Result:** 20,000 items with an unknown key went from 1,478 ms to well under 1 s, as asserted in
  `tests/run.php`. A 60,000-key body over HTTP was answered with 422 in 0.12 s; it took 13.8 s before the fix.

### R2-02 — Exception traces recorded argument values

- `src/bootstrap.php`: `ini_set('zend.exception_ignore_args', '1')` for web and CLI.
- `#[\SensitiveParameter]` added to:
  - `Password::hash`, `verify` and `needsRehash`;
  - `Model::create`, `update` and `run`;
  - `JWT::checkedSecret`;
  - `SMTPMailer::command` and `write`;
  - `User::authenticate`.

  These parameters stay hidden even if a host overrides the ini setting.

### R2-03 — A NUL byte in a password caused a 500

- `src/Auth/Password.php`: `hash()` throws `ValidationException` (422) for a NUL character, and `verify()` returns
  `false` for one. `configure()` now defaults to cost 12.

### R2-04 — World-readable runtime files

- `src/Logging/RequestLogger.php`, `src/Logging/ErrorLogger.php`: new daily log files are set to `0640`. The log
  directory is still created as `0750`.
- `src/RateLimit/RateLimiter.php`: new records are set to `0660` and the directory is created as `0770`, so the CLI
  and the web server can share them through a group without other accounts reading them.
- `README.md`: notes `chmod -R o-rwx storage` for files created before this change.

### R2-05 — A backup could commit an open transaction

- `src/Database/DatabaseBackup.php`: `createZIP()` throws an exception if the connection has an open transaction.

### R2-06 — Strict templates and the README example

- `app/Views/example.php`: loops over `$cars ?? []`.
- `README.md`: documents that templates fail on PHP warnings and need defaults for optional variables.

### R2-07 — SMTP accepted TLS 1.0 and 1.1

- `src/Mail/SMTPMailer.php`:
  - STARTTLS negotiates only TLS 1.2 or 1.3;
  - `ssl://` connections use a context with the same `crypto_method`, plus `verify_peer`, `verify_peer_name` and
    `peer_name`.

### R2-08 — The logger decoded oversized bodies

- `src/Logging/RequestLogger.php`: `input()` compares the raw body size with `max_input_bytes` before decoding.

### R2-09 — Log pruning was too broad

- `src/Logging/LogFiles.php`: `prune()` deletes only `Y-m-d.log` and `errors-Y-m-d.log`. Other dated files in the
  directory are left alone.

### R2-10 — Deprecations flooded the error log

- `src/Core/ErrorHandler.php`: each deprecation location (`file:line`) is logged once per process, with the current
  request when there is one.

### R2-11 — Malformed claim types caused a 500

- `src/Auth/JWT.php`: `validateClaims()` requires `iss`, `sub` and `jti` to be non-empty strings, and `aud` to be a
  string or a list of strings. Otherwise it throws `JWTException`.
- `app/Middlewares/AuthMiddleware.php`: rejects a token whose `sv` isn't an integer before loading the user, then
  compares strictly.

### R2-12 — No statement timeout

- `src/Database/Database.php`: the new `setStatementTimeout()` sets `max_execution_time` in milliseconds on MySQL or
  `max_statement_time` in seconds on MariaDB. It is applied on connect when the connection's `statement_timeout_ms` is
  above 0.
- `src/Database/DatabaseBackup.php`: removes the limit on its own session before dumping.
- `config/app.php`: added `statement_timeout_ms` (0, disabled) and comments on both timeouts.
- **Not verified:** `SET time_zone` and the statement timeout on a real MySQL server. The local server rejects the
  configured credentials.

### R2-13 — Clients chose the request id

- `src/Http/Request.php`: `requestId()` is always a random server value. The new `clientRequestId()` returns the
  client's `X-Request-ID` when it is 8–64 letters, digits or dashes.
- `src/Logging/RequestLogger.php`, `src/Logging/ErrorLogger.php`: log `client_request_id` next to `request_id`.

### R2-14 — Smaller items

- **Fatal-error responses:** `src/Core/ErrorHandler.php` adds `setRequest($request, $headers)`, which
  `src/Core/Application.php` calls at the start of `dispatch()`. A fatal error is now logged with its request, and the
  500 response carries `X-Request-ID`, `X-Content-Type-Options` and the request's CORS headers.
- **Attachment names:** `src/Http/Response.php` `attachment()` sends an ASCII `filename` plus an RFC 5987
  `filename*=UTF-8''…` when the name isn't plain ASCII. Backslashes are treated as path separators.
- **View CSP:** `src/Http/Response.php` `view()` adds
  `Content-Security-Policy: default-src 'self'; base-uri 'none'; form-action 'self'; frame-ancestors 'none'`. Calling
  `header()` after `view()` overrides it.
- **Generator:** `src/Core/MakeCommand.php` rejects PHP keywords and reserved type names as class names (Codex F31).
- **Deploy check:** `cli/check-deploy` also probes today's and yesterday's request logs, today's error log, files in
  `storage/backups/` and `storage/uploads/`, `/tests/run.php` and `/CLAUDE_QA_REVIEW_2.md`, for 22 paths in total.
- **`.htaccess`:** blocks the new `tests/` directory.
- **Tests:** `tests/run.php` (new) contains 29 dependency-free regression tests covering:
  - request input and identity, routing, responses and logging;
  - the validator limits, including R2-01;
  - JWT, including rotation, tampering and claim types;
  - passwords;
  - `Model` and transactions on a temporary SQLite file;
  - uploads, SMTP and the generator.

  It exits with code 1 on any failure.
- **Docs:** `AGENTS.md` adds `tests` to the lint command and documents `php tests/run.php`. `README.md` and
  `PROJECT.md` describe the tests and the new behavior.

## Round-1 open items

### FW-07 — Stable error shape

Every error response is now:

```json
{"success": false, "message": "Invalid Data", "errors": {"email": ["The email field is required."]}, "data": null}
```

- `src/Validation/ValidationException.php`:
  - holds errors keyed by field;
  - a plain list of messages becomes request-level errors under `_request`;
  - the message is always `Invalid Data`.
- `src/Validation/Validator.php`: field errors and unknown-key errors are keyed by field path. At most 50 fields are
  returned; when there are more, `_request` ends with `Additional errors were omitted.`
- `src/Http/Request.php`: a query parameter rejected on a write request is reported under its own name, and a body sent
  with `GET` under `_request`.
- `src/Auth/Password.php`: a NUL character is reported under `password`.
- `src/Http/Response.php`: `error(string $message, int $status, array $errors = [], mixed $data = null)` always sends
  `message` as a string and `errors` as an object (`{}` when empty).
- `src/Core/Application.php`, `src/Core/Debugger.php`, `src/Core/ErrorHandler.php`: the 422 response, the disabled
  debug dump and the fatal-error response all use the same shape.
- `app/Middlewares/AuthMiddleware.php`, `app/Controllers/AuthController.php`, `app/Controllers/HealthController.php`:
  callers updated.

### FW-03 — Rate limiting

- `src/RateLimit/RateLimiter.php` (rewritten):
  - **Global limit:** `check()` counts each client before routing. A client is an IPv4 address or an IPv6 /64
    (`ipv6_prefix`).
  - **Counters for any key:** `hit()`, `attempts()` and `clearKey()` count per user or per login username.
  - **No escalation:** the old pause, violation and timed-block cycle is gone.
  - **Manual blocks:** `block()` and `clear()` manage permanent blocks, stored in `storage/rate-limiter/blocked/`.
  - **Cleanup:** `prune()` deletes counters unused for `record_ttl_seconds`. It runs on about 1% of requests, under a
    non-blocking lock.
  - **Writes are checked,** and failures surface, so a full disk cannot silently reset counters.
  - **Upgrade:** the first run moves permanent blocks from the old one-file-per-IP layout and removes the old counters.
- `src/RateLimit/RateLimitDecision.php`: builds the 403 (blocked) or 429 response, with `Retry-After`,
  `data.retry_after` and the `X-RateLimit-*` headers.
- `src/Http/IPAddress.php`: new `network()`, which masks an address to its /64 or any other prefix.
- `app/Middlewares/ThrottleMiddleware.php` (new): `throttle:<max>,<seconds>` counts per signed-in user, or per client
  for guests. Storage errors are logged and the request is allowed.
- `app/Controllers/AuthController.php`: failed logins are counted per username with `attempts()` and `hit()`, and a
  successful login calls `clearKey()`.
- `routes/api.php`: every authenticated route has `throttle:120,60`.
- `config/app.php`:
  - `max_requests` is now 600 per minute per client;
  - added `ipv6_prefix`, `login_max_attempts` (5), `login_window_seconds` (900) and `record_ttl_seconds` (86,400);
  - removed `pause_minutes`, `max_violations`, `block_minutes` and `violation_decay_minutes`;
  - added the `throttle` middleware alias.
- `cli/rate-limit`: added `prune`.
- **Not done:** a MySQL-backed counter store for running several web servers. File counters are still local to one
  server, as the README notes.

### FW-05 — Database-backed sessions

The design follows the owner's choice:

- one session per user;
- a random token stored as a SHA-256 hash;
- a 7-day sliding idle expiry with a 90-day absolute limit;
- no refresh endpoint;
- logout, a password change or deactivation deletes the session.

**Files:**

- `src/Auth/SessionToken.php` (new): generates and hashes tokens, and rejects malformed ones before any database
  lookup.
- `app/Models/UserSession.php` (new):
  - `start()` replaces the user's session in one statement (`ON DUPLICATE KEY UPDATE` on the unique `user_id`);
  - `findActive()` deletes and rejects an expired session;
  - `touch()` slides the expiry, at most once per `session_touch_seconds` and never past the absolute limit;
  - `endForUser()` ends the session;
  - `deleteExpired()` runs at every login.
- `app/Middlewares/AuthMiddleware.php`: authenticates by session instead of JWT, ends the session of an inactive user,
  and extends the expiry.
- `app/Controllers/AuthController.php`: login returns `token`, `token_type`, `expires_at` and `absolute_expires_at`.
  Logout ends the session. `refresh` was removed.
- `app/Controllers/UserController.php`: a password change or deactivation ends the user's session. A role change no
  longer signs out, because permissions are reloaded on every request.
- `app/Models/User.php`: removed `session_version` and `incrementSessionVersion()`.
- `src/Auth/AccessToken.php`: deleted; it only existed to build JWTs with `session_version`. The `JWT` class remains for
  other signed tokens.
- `routes/api.php`: removed `POST /auth/refresh`.
- `config/app.php`:
  - new `auth` section: `session_idle_seconds` (604,800, 7 days), `session_lifetime_seconds` (7,776,000, 90 days) and
    `session_touch_seconds` (3,600);
  - startup check that `60 <= idle <= lifetime`.
- `migrations/2026_08_25_000001_init_project.php`: fresh installs get `user_sessions` (unique `user_id`, unique
  `token_hash`, an `expires_at` index, and a foreign key to `users` with `ON DELETE CASCADE`) and no `session_version`.
- `migrations/2026_10_14_173933_create_user_sessions_table.php` (new):
  - adds `user_sessions` to databases created before this change;
  - does nothing on fresh installs;
  - leaves the unused `users.session_version` column in place, so no existing data is dropped.

**API change for the Android app:**
- Store `token` and send it as `Authorization: Bearer <token>`.
- There is no refresh call: on any 401, show the login screen.
- Logging in on another device signs out this one.

## Other fixes found while verifying

- **`php cli/migrate.php` never worked.** `config/app.php` ran its startup checks in the caller's scope, and its
  `$connection` variable overwrote the migrate script's connection argument, which caused a `TypeError`. The checks now
  run inside a closure that returns the config, so requiring the file defines nothing in the caller.
- **Statement timeout:** `Database::setStatementTimeout()` (R2-12) failed on MySQL with error 1232, because a bound
  parameter arrives as a string. The clamped integer is now written into the statement.
- **Rollback guard:** `php cli/migrate.php rollback` now refuses in **every** environment unless `--force` is given. It
  prints the migrations it would reverse and exits with code 1.

## Incident: local database rolled back during verification

While testing the migrate CLI, I ran `php cli/migrate.php rollback` against the local `expressphp_db`. It expected
the production guard to refuse, but `env` was `development`, so the rollback dropped the application tables. This is
why rollback now always requires `--force`.

Afterwards the owner re-ran the migration and created new accounts. The additive migration above then added
`user_sessions` without touching them. User `akbar` (id 13) and three activity log rows from before the rollback can
still be recovered from MySQL's binary log, if wanted.
